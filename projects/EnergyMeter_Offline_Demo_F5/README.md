# EnergyMeter Offline — учебная демонстрация по F5

Вариант 15. Модуль офлайн-буферизации на SQLite + EF Core + Polly (.NET 8).

## Как запустить

1. Распакуйте ZIP в отдельную папку.
2. Откройте `EnergyMeter.Offline.sln` в Visual Studio 2022.
3. Убедитесь, что установлен .NET 8 SDK и восстановлены пакеты NuGet.
4. Нажмите **F5**. Аргументы и сервер не нужны.
5. Дождитесь итоговой строки `ВСЕ ДЕМО-ТЕСТЫ ПРОЙДЕНЫ`.

Демонстрация использует настоящую SQLite-базу и EF Core. В нее записываются
пять тестовых показаний. Затем моделируется отсутствие сети: данные остаются
в таблице `Outbox`. При имитации восстановления связи первый запрос дважды
получает статус HTTP 503, Polly выполняет повторы, после чего показания
переносятся в таблицу `ReceivedEvents` — локальный макет получателя.

Уникальный индекс по `EventId` в SQLite предотвращает повторную регистрацию.
После закрытия и повторного открытия базы проверяется сохранность записей.

## Результаты и скриншоты

Каждый запуск создает новую папку `DemoOutput\yyyyMMdd-HHmmss-fff\` с файлами:

- `energymeter-demo.sqlite` — база SQLite с таблицами `Outbox` и `ReceivedEvents`;
- `queued-before-sync.csv` — пять записей до синхронизации;
- `demo-report.txt` — результаты проверок с PASS или FAIL.

Для отчета рекомендуется снять три скриншота: консоль F5, файл
`demo-report.txt`, содержимое папки `DemoOutput` или таблиц SQLite.

## Исходные команды (по желанию)

Режим с аргументами сохранен:

```powershell
dotnet run -- enqueue b6764e22-92e1-4be0-9f32-f40c3d849d12 15.3
dotnet run -- flush http://localhost:5000 "ключ-API"
```

Для `flush` в командном режиме требуется работающий API EnergyMeter с
проверкой `X-API-Key` и идемпотентностью по `X-Event-Id`.

**Ограничение:** деморежим намеренно не подключается к настоящему серверу.
Он демонстрирует хранение, восстановление и работу Polly на локальном
имитаторе HTTP-ответов. Применение в Production требует миграций БД,
мониторинга, защиты секретов, устойчивого транспорта и автоматических тестов.
