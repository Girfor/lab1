# EnergyMeter API — демонстрационная версия (вариант 15)

Готовый пример на ASP.NET Core 8 для Windows / Visual Studio 2022. Сервер запускается локально на вашем компьютере, внешний сервер, база данных, API-ключи и аргументы командной строки не нужны.

## Запуск по F5

1. Распакуйте ZIP целиком в новую папку. Не переносите отдельно файл решения.
2. В Visual Studio откройте файл EnergyMeter.Api.Demo.sln из корня распакованной папки.
3. При первом запуске дождитесь восстановления NuGet-пакетов (для их первой загрузки может понадобиться интернет).
4. Запустите решение кнопкой F5. Единственный проект EnergyMeter.Api.Demo уже является запускаемым.
5. Откроется браузер со страницей http://127.0.0.1:5162/demo. Если браузер не открылся сам, введите этот адрес вручную.
6. Дождитесь 18 × PASS и надписи ИТОГ: PASS. Те же результаты появятся в консоли Visual Studio.
7. Откройте созданный отчёт по пути, напечатанному в консоли. Обычно это:
   EnergyMeter.Api.Demo/DemoOutput/<дата-время>/demo-report.txt.

ВНИМАНИЕ: В отличие от предыдущих консольных программ, веб-API должен оставаться запущенным, пока вы просматриваете страницу в браузере. Остановить его можно сочетанием Shift+F5 или кнопкой «Остановить отладку» в Visual Studio.

Если порт 5162 уже занят другим приложением, закройте приложение, использующее этот порт, прежде чем запускать демонстрацию.

## Что проверяется автоматически

| Группа | Проверки |
| --- | --- |
| Веб-интерфейс | Стартовая страница доступна |
| REST API | GET v1, GET v2, запись, идемпотентность X-Event-Id, валидация полей, расширенное поле quality в v2 |
| Доступ | Запись без API-ключа и с неверным ключом отклоняется |
| Swagger | UI доступен в Development, условие запрещает Swagger в Production |
| Администрирование | Без авторизации CSRF-токен не выдается; неправильный вход отклоняется |
| CSRF | Учебная cookie-сессия, выдача токена, запрет POST без токена и разрешение POST с правильным токеном |

Программа создаёт временный случайный API-ключ и код входа администратора только в памяти текущего процесса. Демо-авторизация открыта лишь в Development, а сам сервер слушает только 127.0.0.1. Никаких реальных учётных данных, постоянных паролей или внешних серверов нет.

## Маршруты после запуска

- http://127.0.0.1:5162/demo — страница с результатами тестирования
- http://127.0.0.1:5162/api/v1/readings — список показаний v1 (JSON)
- http://127.0.0.1:5162/api/v2/readings — список показаний v2 (JSON, поле quality)
- http://127.0.0.1:5162/swagger/index.html — Swagger UI только при разработке

Примечание по безопасности: для простоты учебной демонстрации используется HTTP на loopback. В реальной сети обязателен HTTPS, а администрирование должно использовать настоящую систему учётных записей. Тест условия Swagger/Production не запускает отдельный Production-сервер. Результаты PASS означают успешное прохождение этих конкретных локальных проверок, а не независимый аудит.

## Чем исправлена предыдущая ошибка

В архиве одно решение и один исполняемый проект с корректным относительным путём. Поэтому не возникает ошибки о поиске C:\Users\...\src\EnergyMeter.Api\EnergyMeter.Api.csproj. Для главной страницы / добавлено перенаправление на /demo, поэтому при F5 нет 404.
