# EnergyMeter Security — демонстрация (вариант 15)

Готовое решение для Visual Studio и **Windows**, .NET 8. Запускается по F5 **без аргументов, без сервера и без сети**.

## Быстрый запуск

1. Распакуйте архив полностью в отдельную папку.
2. Откройте файл **EnergyMeter.Security.Demo.sln** в Visual Studio 2022 или новее с установленным .NET 8 SDK.
3. В верхней панели выберите запускаемый проект **EnergyMeter.Security.Demo** (в обычном случае уже выбран). Если нужно: нажмите правой кнопкой по этому проекту → «Назначить запускаемым проектом».
4. Нажмите **F5**.
5. Дождитесь десяти строк `PASS` и финального сообщения `ИТОГ: ВСЕ ДЕМО-ТЕСТЫ ПРОЙДЕНЫ`.
6. Откройте файл отчёта из выведенного в консоль пути. Это `EnergyMeter.Security.Demo/bin/Debug/net8.0/DemoOutput/<дата-время>/demo-report.txt`.

При первом запуске Visual Studio может восстановить NuGet-пакеты. **Тесты не требуют интернета**, но первоначальная загрузка NuGet-зависимостей на новом компьютере может потребовать подключение, если пакеты ещё не установлены.

## Устройство решения

| Проект | Тип | Назначение |
| --- | --- | --- |
| `EnergyMeter.Security` | Class Library | DPAPI, BCrypt, X.509, безопасный HttpClient |
| `EnergyMeter.Security.Demo` | Console App | Автоматическая проверка механизмов, отчёт PASS/FAIL |

**Важно:** библиотека `EnergyMeter.Security` сама по себе не запускается по F5; точка входа находится в `EnergyMeter.Security.Demo`. Не меняйте тип выходных данных библиотеки на «Консольное приложение», иначе получите ошибку CS5001.

## Проверки (10)

1. Шифрование и расшифрование DPAPI в профиле текущего пользователя Windows.
2. Обнаружение повреждённых зашифрованных данных.
3. BCrypt: правильный пароль принят.
4. BCrypt: неверный пароль отклонён.
5. BCrypt: автоматическая соль даёт разные хеши для одного пароля.
6. X.509: проверка подписанного сертификата с временно доверенным локальным корнем.
7. X.509: сертификат от неизвестного корня отклонён.
8. X.509: просроченный сертификат отклонён.
9. X.509: сертификат без назначения Server Authentication отклонён.
10. Создание HTTP-клиента со штатной проверкой TLS и списков отзыва.

В демонстрации сертификаты создаются **в оперативной памяти**, в системное хранилище не записываются. Для теста доверенного корня используется локальный `CustomRootTrust`; он не ослабляет обычную проверку сертификатов по системному хранилищу. Сеть и серверы не вызываются.

В отчёте `PASS` означает, что соответствующая проверка действительно выполнилась. При исключении или неверном результате будет `FAIL` и код завершения 1. Тесты не заменяют полноценный аудит безопасности.
