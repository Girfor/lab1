# EnergyMeter Auto-Updater — демонстрация по F5

Вариант 15 — EnergyMeter System, МДК 03.01.

## Запуск в Visual Studio 2022

1. Распакуйте архив в обычную папку, например `Документы\EnergyMeterUpdaterDemo`.
2. Дважды щелкните `EnergyMeter.Updater.sln` (или откройте `EnergyMeter.Updater.csproj`).
3. Убедитесь, что установлен .NET 8 SDK.
4. Нажмите **F5** или **Ctrl+F5**. Аргументы и сервер не нужны.
5. После завершения увидите строку `ИТОГ: ВСЕ ДЕМО-ТЕСТЫ ПРОЙДЕНЫ`.

Программа сама формирует ZIP с текстовой заметкой о версии 1.1.0, создает
`manifest.json`, вычисляет SHA-256, копирует пакет в `staging`, проверяет
хеш и отдельно убеждается, что измененный пакет обнаруживается.

Результаты каждого запуска помещаются в новую папку:

`DemoOutput\yyyyMMdd-HHmmss-fff\`

Внутри находятся `manifest.json`, `releases\`, `staging\`,
`tampered-package.zip` и `demo-report.txt`. Все файлы демонстрационные.

## Что показать преподавателю на скриншотах

1. Консоль со строками `[1]`–`[7]` и успешным итогом.
2. Содержимое `manifest.json` с версией и контрольной суммой.
3. Папку `staging` с проверенным ZIP.
4. `demo-report.txt` с результатом `PASS`.

## Дополнительный режим для настоящего HTTPS-сервера

При передаче трех аргументов используется исходный режим:

```powershell
dotnet run -- 1.0.0 https://updates.example.org/manifest.json .\staging
```

Для этого нужен действительный HTTPS-манифест, реальный ZIP и совпадающий
SHA-256. Обновление только помещается в staging; исполняемый код не запускается
и не устанавливается автоматически. В рабочей системе дополнительно нужна
криптографическая подпись издателя, атомарное развертывание и откат.

Примечание: демоверсия не устанавливает обновление и не обращается к сети.
